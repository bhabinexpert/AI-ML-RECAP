Unsupervised Learning & NLP

No labels this time. Here the model has to find its own structure in data — and we apply that idea specifically to text, where "structure" means turning words into numbers.

5.1 Unsupervised vs. Supervised Learning

SupervisedUnsupervised
DataLabeled (X, y)Unlabeled (X only)
GoalPredict a known targetDiscover hidden structure/groups
EvaluationCompare prediction vs. true label (accuracy, RMSE, etc.)No ground truth — evaluated indirectly (e.g. cluster cohesion, silhouette score)
ExamplesSpam detection, price predictionCustomer segmentation, anomaly detection, topic discovery

5.2 Clustering

Definition
Clustering groups data points so that points in the same group (cluster) are more similar to each other than to points in other groups, based purely on feature similarity/distance — no labels involved.

K-Means — the standard process

  1. Choose the number of clusters, K.
  2. Randomly initialize K "centroids" (cluster centers).
  3. Assign every point to its nearest centroid.
  4. Recompute each centroid as the mean of the points assigned to it.
  5. Repeat steps 3–4 until centroids stop moving (convergence).
from sklearn.cluster import KMeans
model = KMeans(n_clusters=3, n_init=10)
labels = model.fit_predict(X)  # scale X first — K-Means is distance-based

Choosing K: the Elbow Method

Plot "within-cluster sum of squares" (inertia) against different values of K — the point where the curve bends like an elbow is a reasonable choice for K.

Advantages of clustering

  • No labels needed — cheap to apply to raw data
  • Reveals structure you didn't know to look for
  • Fast (K-Means scales well)

Disadvantages / limitations

  • You must choose K in advance (K-Means)
  • Assumes roughly spherical, similar-sized clusters — struggles with irregular shapes
  • Sensitive to feature scale and outliers
  • No ground truth to check "correctness" against
  • Results can vary with random centroid initialization

5.3 DBSCAN

Definition
DBSCAN (Density-Based Spatial Clustering) groups points that are closely packed together (high density), and marks points in low-density regions as noise/outliers — unlike K-Means, it does not require you to specify the number of clusters in advance, and it can find arbitrarily shaped clusters.
  • ε (epsilon) — the radius to search around each point for neighbors.
  • MinPts — the minimum number of neighbors within ε required for a point to be a "core point".
  • Core points close to each other get chained into the same cluster; points too far from any core point become noise.
from sklearn.cluster import DBSCAN
model = DBSCAN(eps=0.5, min_samples=5)
labels = model.fit_predict(X)  # label -1 means "noise / outlier"

Advantages

  • Finds arbitrarily-shaped clusters
  • Doesn't require choosing K
  • Naturally identifies outliers/noise

Disadvantages

  • Sensitive to ε and MinPts choices
  • Struggles when clusters have very different densities

5.4 Dimensionality Reduction

Definition
Compressing a dataset with many features into fewer "components" while retaining as much important information (variance) as possible — used for visualization, speeding up training, and fighting the curse of dimensionality.

PCA (Principal Component Analysis) is the standard technique: it finds new axes (principal components) that are linear combinations of the original features, ordered by how much variance in the data they capture. Keeping just the first 2–3 components often preserves most of the signal.

from sklearn.decomposition import PCA
pca = PCA(n_components=2)
X_reduced = pca.fit_transform(X_scaled)  # scale first — PCA is variance-based
print(pca.explained_variance_ratio_)     # % of information kept per component
Trade-off
You gain speed and can visualize high-dimensional data in 2D/3D, but the new components are combinations of original features and lose direct interpretability — you can no longer say "feature X mattered," only "component 1 mattered."

5.5 Approach to NLP (Natural Language Processing)

Definition
NLP is the field of getting computers to work with human language. Since ML models only understand numbers, the entire NLP pipeline is about responsibly turning messy text into clean numeric vectors without losing the meaning that matters for the task.

The NLP Pipeline

  1. Getting data — scraping, APIs, existing text corpora, user-generated content.
  2. Text cleaning — lowercasing, removing punctuation/HTML tags/special characters, removing stopwords ("the", "is", "and"), stemming/lemmatization (reducing words to their root form).
  3. Tokenization — splitting text into words or sub-word units.
  4. Vectorization — converting tokens into numeric vectors (below).
  5. Modeling — feeding vectors into a classifier/regressor/neural network.
Python — text cleaning
import re
from nltk.corpus import stopwords
from nltk.stem import WordNetLemmatizer

def clean_text(text):
    text = text.lower()
    text = re.sub(r"[^a-z\s]", "", text)               # strip punctuation/numbers
    words = [w for w in text.split() if w not in stopwords.words("english")]
    lemmatizer = WordNetLemmatizer()
    return " ".join(lemmatizer.lemmatize(w) for w in words)

5.6 Vectorization

One-Hot Encoding (for text)

Every unique word in the vocabulary gets its own column; a sentence is represented by marking which words are present. Extremely sparse and ignores word order/frequency — rarely used alone in modern NLP, but foundational to understand.

Bag of Words (BoW)

Represents each document as a vector of word counts — like one-hot but keeping frequency information. Ignores grammar and word order entirely (hence "bag").

from sklearn.feature_extraction.text import CountVectorizer
vectorizer = CountVectorizer()
X = vectorizer.fit_transform(documents)  # rows = docs, columns = vocabulary word counts

TF-IDF (Term Frequency – Inverse Document Frequency)

Improves on BoW by down-weighting words that appear in many documents (like "the", which carries little distinguishing information) and up-weighting words that are frequent in a specific document but rare across the corpus (more informative).

TF-IDF(t, d) = TF(t, d) × IDF(t)
TF(t,d) = (count of term t in document d) / (total terms in d)
IDF(t) = log( total documents / documents containing t )
from sklearn.feature_extraction.text import TfidfVectorizer
vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(documents)
MethodCaptures frequency?Down-weights common words?Captures order?
One-HotNo (binary presence)NoNo
Bag of WordsYesNoNo
TF-IDFYesYesNo
Beyond this module
None of these methods capture word meaning or order — that's what word embeddings (Word2Vec, GloVe) and transformer models (BERT, GPT) were built to solve, by learning dense vectors where similar-meaning words end up close together.
