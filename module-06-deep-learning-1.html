Deep Learning I — Neural Network Foundations

Every neural network — from a 3-neuron toy example to GPT — is built from the same handful of ideas covered here: a neuron, an activation, a loss, and an optimizer.

6.1 The Perceptron

Definition
The perceptron is the simplest possible neural network unit: it takes inputs, multiplies each by a weight, sums them with a bias, and passes the result through an activation function to produce an output.
z = w₁x₁ + w₂x₂ + ... + wₙxₙ + b
output = activation(z)

A single perceptron with a sigmoid activation is, mathematically, exactly logistic regression (Module 03). Deep learning's power comes from stacking many of these units into layers.

6.2 Artificial Neural Networks (ANN)

Definition
An ANN stacks neurons into layers: an input layer (raw features), one or more hidden layers (each neuron connected to every neuron in the previous layer — "fully connected" / "dense"), and an output layer (the prediction). Stacking layers lets the network learn increasingly abstract combinations of the input features.

6.3 Forward & Backward Propagation

Forward Propagation

Data flows left to right through the network: each layer computes z = Wx + b, applies an activation function, and passes the result to the next layer, until the output layer produces a final prediction. This prediction is compared to the true label using a loss function.

Backward Propagation (Backprop)

To improve, the network needs to know how much each weight contributed to the error. Backprop applies the chain rule from calculus, working backward from the output layer to the input layer, computing the gradient of the loss with respect to every weight in the network.

∂L/∂wᵢⱼ = ∂L/∂output × ∂output/∂z × ∂z/∂wᵢⱼ
Each layer's gradient depends on the gradient computed in the layer after it — this is exactly the chain rule, applied layer by layer, moving backward.

Once every gradient is known, each weight is updated using gradient descent (Module 02):

w := w − α · ∂L/∂w
Epoch
One epoch = one complete pass of the entire training dataset through the network (forward + backward + weight update for every batch). Training usually runs for many epochs until the loss stops improving.

6.4 The Vanishing Gradient Problem

The problem
In deep networks, gradients are computed by multiplying many small numbers together (chain rule across many layers). If each layer's gradient is a fraction less than 1 (as with sigmoid/tanh, whose derivatives max out at 0.25 and 1.0 respectively but are usually much smaller), the product shrinks exponentially the further back you propagate — early layers end up receiving a gradient so close to zero that they barely learn at all.

Why it matters: this was the main reason very deep networks were hard to train for years. It's a key motivation behind ReLU-family activations (they don't saturate for positive inputs) and architectural fixes like residual/skip connections.

6.5 Activation Functions

An activation function introduces non-linearity. Without one, stacking any number of layers collapses mathematically into a single linear function — no amount of depth would let the network learn curved decision boundaries or complex patterns.

Linear Activation

f(z) = z

Used only in output layers for regression (predicting an unbounded real number). Never used in hidden layers — stacking linear layers is mathematically equivalent to one linear layer, defeating the point of depth.

Sigmoid

f(z) = 1 / (1 + e^(−z)) → range (0, 1)

Good for output layer of binary classification (interpretable as probability). Rarely used in hidden layers of deep networks — it saturates (flattens) for large |z|, causing vanishing gradients.

Tanh (Hyperbolic Tangent)

f(z) = (eᶻ − e⁻ᶻ) / (eᶻ + e⁻ᶻ) → range (−1, 1)

Zero-centered (unlike sigmoid), which usually helps optimization converge faster than sigmoid — but it still saturates at extreme values, so it also suffers from vanishing gradients in deep networks.

ReLU (Rectified Linear Unit)

f(z) = max(0, z)

The default choice for hidden layers in most modern networks. Computationally cheap, doesn't saturate for positive inputs (so gradients flow well), and empirically trains faster than sigmoid/tanh.

The Dying ReLU Problem
If a neuron's weighted input z is consistently negative, ReLU outputs exactly 0 and its gradient is also exactly 0 — that neuron stops updating entirely and "dies," never activating again for any input. A large learning rate or bad initialization can cause many neurons to die this way.

Leaky ReLU

f(z) = z if z > 0, else α·z (α is a small constant, e.g. 0.01)

Fixes dying ReLU by allowing a small, non-zero gradient when z is negative, so the neuron can still recover.

PReLU (Parametric ReLU)

Same shape as Leaky ReLU, but α is learned during training instead of being a fixed hyperparameter — lets the network decide the optimal amount of "leak" per neuron.

Swish

f(z) = z · sigmoid(z)

A smooth, non-monotonic activation (discovered via automated search at Google) that often outperforms ReLU on deeper networks, at a small extra computational cost.

6.6 Loss Functions

Regression losses

LossFormula (per sample)Notes
MAE (Mean Absolute Error)|y − ŷ|Robust to outliers, gradient has constant magnitude
MSE (Mean Squared Error)(y − ŷ)²Penalizes large errors heavily; smooth gradient, most common default
MSLE (Mean Squared Log Error)(log(1+y) − log(1+ŷ))²Useful when the target spans orders of magnitude and relative error matters more than absolute error

Classification losses

LossUse caseNotes
Binary Cross-EntropyBinary classificationSame as "log loss" from Module 03
Categorical Cross-EntropyMulti-class, one-hot labelsPairs with softmax output activation
Sparse Categorical Cross-EntropyMulti-class, integer labelsSame math as above, saves you from one-hot encoding labels manually
Categorical Cross-Entropy = − Σᵢ yᵢ · log(ŷᵢ)
Summed over all classes i; yᵢ is 1 for the true class and 0 elsewhere (one-hot), so only the predicted probability assigned to the true class actually affects the loss.
model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])

6.7 Optimizers

An optimizer is the specific rule used to update weights using the gradients from backprop. They differ mainly in how much data they use per update and how they adapt the step size.

Batch Gradient Descent

Uses the entire training set to compute one gradient, then makes one update per epoch. Very stable direction, but slow and memory-heavy on large datasets.

Stochastic Gradient Descent (SGD)

Updates weights after every single training example. Very fast per update and can escape shallow local minima due to its noisy path, but the noisy path also makes convergence unstable/jittery.

Mini-Batch Gradient Descent

The practical middle ground used almost everywhere: compute the gradient over a small batch (e.g. 32, 64, 128 samples) at a time. Balances the stability of batch GD with the speed and regularizing noise of SGD.

Momentum

Adds a fraction of the previous update to the current one — like a ball rolling downhill that builds up speed — smooths out oscillations and speeds up convergence in consistent directions.

AdaGrad

Adapts the learning rate per parameter, shrinking it for parameters that have received large gradients already (frequently-updated features) and keeping it larger for rarely-updated ones. Downside: the learning rate only ever shrinks and can become too small to keep learning.

Adam (Adaptive Moment Estimation)

Combines the ideas of Momentum (tracking a moving average of past gradients) and AdaGrad/RMSProp (adapting the learning rate per parameter, but with a decaying average so it doesn't shrink forever). It's the default, most widely used optimizer today for good reason — fast convergence with minimal manual tuning.

model.compile(optimizer=tf.keras.optimizers.Adam(learning_rate=0.001),
              loss="categorical_crossentropy")

Why does ReLU generally train deep networks faster than sigmoid?
