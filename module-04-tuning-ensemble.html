Module 04

Model Tuning & Ensemble Learning

A single model has a ceiling. This module covers squeezing more performance out of one model (tuning) and combining many models into one stronger one (ensembling).

4.1 Cross-Validation

Definition
Cross-validation (CV) evaluates a model more reliably than a single train/test split by splitting the data into K folds, training on K−1 of them and testing on the remaining fold, rotating which fold is held out, and averaging the K results. 
from sklearn.model_selection import cross_val_score
scores = cross_val_score(model, X, y, cv=5, scoring="accuracy")
print(scores.mean(), scores.std())  # mean performance + how stable it is across folds
Why not just one train/test split?
A single split gives one noisy estimate — you might get lucky or unlucky with which rows land in test. CV averages over multiple splits, giving both a more reliable mean score and a sense of variance.

4.2 Hyperparameter Tuning

Definition
Hyperparameters are settings you choose before training (like K in KNN, max_depth in a tree, or the learning rate) — unlike model parameters (weights), they aren't learned from data automatically. Tuning searches for the combination that performs best, using cross-validation to score each candidate.

Grid Search CV

Exhaustively tries every combination in a predefined grid of hyperparameter values. Guaranteed to find the best combination within the grid, but the number of combinations explodes quickly as you add more hyperparameters or more values per hyperparameter.

from sklearn.model_selection import GridSearchCV
param_grid = {"n_estimators": [100,200,300], "max_depth": [3,5,7]}
grid = GridSearchCV(model, param_grid, cv=5, scoring="f1")
grid.fit(X_train, y_train)
print(grid.best_params_, grid.best_score_)

Randomized Search CV

Instead of trying every combination, it samples a fixed number of random combinations from the specified ranges — much faster, and in practice often finds a near-optimal combination far quicker than an exhaustive grid, especially when many hyperparameters barely affect performance.

from sklearn.model_selection import RandomizedSearchCV
random_search = RandomizedSearchCV(model, param_distributions=param_grid, n_iter=20, cv=5)
random_search.fit(X_train, y_train)
Grid SearchRandomized Search
Exhaustive — tries all combinationsSamples a fixed number of random combinations
Guaranteed best-in-grid resultMay miss the absolute best, usually close enough
Expensive as grid growsCost is fixed regardless of parameter space size

4.3 Ensemble Learning

Definition
Ensemble learning combines multiple models ("weak learners") into one stronger model. The core idea: different models make different errors, so combining their predictions (by voting or averaging) cancels out individual mistakes and improves overall accuracy and stability.
What's a "weak learner"?
A model that performs only slightly better than random guessing on its own (e.g. a decision stump — a tree with just one split). Ensembles combine many weak learners into a collectively strong model.

Three families of ensembling

TypeIdeaExample algorithms
BaggingTrain many models in parallel on random subsets of data, then average/vote — reduces varianceRandom Forest
BoostingTrain models sequentially, each one focusing on the previous model's mistakes — reduces biasAdaBoost, Gradient Boosting, XGBoost
StackingTrain several different models, then train a "meta-model" that learns how to best combine their predictionsStacked ensembles / blending

4.4 Bagging & Random Forest

Bagging (Bootstrap Aggregating)
Draw many random samples with replacement (bootstrap samples) from the training data, train one model per sample independently, then combine their outputs (majority vote for classification, average for regression).
Random Forest
A bagging ensemble of decision trees, with one extra trick: each tree also only considers a random subset of features at every split. This decorrelates the trees so their errors are less alike, making the averaged result more robust than plain bagging of trees. 
from sklearn.ensemble import RandomForestClassifier
model = RandomForestClassifier(n_estimators=200, max_depth=10, max_features="sqrt")
model.fit(X_train, y_train)
importances = model.feature_importances_  # free feature ranking

Advantages

  • Reduces overfitting compared to a single tree
  • Handles high-dimensional data well
  • Provides feature importance for free

Disadvantages

  • Less interpretable than a single tree
  • Slower to predict than a single model
  • Can still struggle with very high-cardinality categorical features

4.5 Boosting: AdaBoost, Gradient Boosting & XGBoost

AdaBoost (Adaptive Boosting)

Trains weak learners (typically decision stumps) one at a time. After each round, it increases the weight of the misclassified samples so the next learner focuses harder on the examples the previous one got wrong. The final prediction is a weighted vote of all learners, weighted by each learner's accuracy.

from sklearn.ensemble import AdaBoostClassifier
model = AdaBoostClassifier(n_estimators=100, learning_rate=1.0)
model.fit(X_train, y_train)

Gradient Boosting

Instead of re-weighting samples, each new tree is trained to predict the residual errors (the gap between actual and current prediction) of the ensemble so far — literally doing gradient descent, but in "function space" rather than parameter space.

from sklearn.ensemble import GradientBoostingClassifier
model = GradientBoostingClassifier(n_estimators=200, learning_rate=0.1, max_depth=3)
model.fit(X_train, y_train)

XGBoost (Extreme Gradient Boosting)

A highly optimized, regularized implementation of gradient boosting — adds L1/L2 regularization on tree weights to fight overfitting, handles missing values natively, and is engineered for speed (parallelized tree construction). It's one of the most consistently winning algorithms on tabular data competitions.

import xgboost as xgb
model = xgb.XGBClassifier(n_estimators=300, learning_rate=0.05, max_depth=4, reg_lambda=1.0)
model.fit(X_train, y_train)

Official docs: xgboost.readthedocs.io

Advantages of boosting

  • Usually higher accuracy than bagging on tabular data
  • XGBoost/LightGBM handle missing values & are very fast

Disadvantages

  • Sequential training → can't parallelize across learners like bagging
  • More prone to overfitting on noisy data if not regularized/tuned
  • More hyperparameters to tune than bagging

4.6 Stacking

Definition
Train several diverse base models (e.g. logistic regression, random forest, SVM), then feed their predictions as input features into a final "meta-model" that learns the best way to blend them. 
from sklearn.ensemble import StackingClassifier
from sklearn.linear_model import LogisticRegression
estimators = [("rf", RandomForestClassifier()), ("svc", SVC(probability=True))]
stack = StackingClassifier(estimators=estimators, final_estimator=LogisticRegression())
stack.fit(X_train, y_train)
Stacking vs. bagging/boosting
Bagging/boosting combine many copies of the same kind of weak learner. Stacking typically combines different kinds of models entirely, betting that their different "views" of the data complement each other.
