Module 01

ML Foundations & Feature Engineering

Before any algorithm, a model is only as good as the data and the process feeding it. This module builds the vocabulary and the pipeline every later module assumes you already know.

1.1 What is Machine Learning?

Definition
Machine Learning (ML) is a way of writing software where, instead of you hand-coding every rule, you feed the computer examples (data) and it works out the rules (a mathematical function) itself, so it can make predictions on examples it has never seen before.

Compare the two approaches directly:

Traditional ProgrammingMachine Learning
You write: Rules + Data → Program → OutputYou provide: Data + Output → Program learns → Rules
Example: "if income > 50k AND age > 30 → approve loan"Example: show the model 100,000 past loan decisions, it discovers the pattern itself
Breaks when the real world has too many exceptions to hand-codeGeneralizes to new, unseen patterns because it learned from examples, not fixed rules

ML sits inside a larger family of technologies. It's worth knowing the boundaries:

  • Artificial Intelligence (AI) — the broad goal: making machines act intelligently (can be rule-based, no learning required).
  • Machine Learning (ML) — a subset of AI: machines that improve at a task by learning from data.
  • Deep Learning (DL) — a subset of ML: learning using multi-layer neural networks, especially strong on unstructured data (images, text, audio).

Why use ML

  • Handles problems too complex to hand-write rules for (e.g. spam detection, image recognition)
  • Improves automatically as more data arrives
  • Finds patterns humans might miss in high-dimensional data

Limitations

  • Needs enough quality data — "garbage in, garbage out"
  • Models can be a black box, hard to explain (especially deep learning)
  • Can quietly learn and amplify biases present in the training data

1.2 Types of Machine Learning

Supervised Learning

The model learns from labeled data: every training example has an input X and a known correct output y. The model's job is to learn the mapping f(X) → y well enough to predict y for brand-new X.

  • Regression — output is continuous (price, temperature, salary).
  • Classification — output is a category (spam/not spam, disease/no disease).

Unsupervised Learning

The model only sees X — no correct answers are given. It must find structure, patterns, or groupings on its own.

  • Clustering — group similar data points together (customer segmentation).
  • Dimensionality Reduction — compress many features into fewer while keeping the important signal (PCA).

Reinforcement Learning (RL)

An agent interacts with an environment, takes actions, and receives rewards or penalties. Over many trials it learns a policy — a strategy that maximizes cumulative reward. There's no fixed "correct answer" dataset; the model learns from consequences of its own actions, similar to how a person learns to ride a bicycle by trying, falling, and adjusting.

Rule of thumb
If you have historical answers to learn from → supervised. If you only have raw data and want to discover structure → unsupervised. If your system needs to make a sequence of decisions and learns from trial-and-error feedback → reinforcement learning.

1.3 Exploratory Data Analysis (EDA)

Definition
EDA is the process of investigating a dataset — before modeling — to understand its structure, spot patterns, find anomalies, and check assumptions, mostly using summary statistics and visualizations.

Why it matters: if you skip EDA and jump straight to modeling, you risk feeding the model outliers, wrong data types, leaked columns, or missing-value patterns that quietly wreck your results. EDA is where you build intuition for the data before trusting any number a model gives you.

Steps of EDA

  1. Understand the data — shape, column names, data types (df.shape, df.info(), df.dtypes).
  2. Descriptive statistics — mean, median, mode, std, min/max, quartiles (df.describe()).
  3. Univariate analysis — study one column at a time: histograms for numeric columns, count plots / bar charts for categorical columns.
  4. Bivariate / multivariate analysis — study relationships between two or more columns: scatter plots, correlation heatmaps, pair plots, box plots grouped by category.
  5. Missing value analysis — how many, where, and is it random or systematic (df.isnull().sum()).
  6. Outlier detection — box plots, IQR method, z-scores.
  7. Correlation analysis — which features move together, and which correlate with the target (helps flag multicollinearity too).
Python — a minimal EDA pass
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt

df = pd.read_csv("data.csv")

# 1. structure
print(df.shape, df.dtypes)

# 2. descriptive stats
print(df.describe(include="all"))

# 3. missing values
print(df.isnull().sum())

# 4. univariate: distribution of a numeric column
sns.histplot(df["age"], kde=True)

# 5. bivariate: correlation heatmap
sns.heatmap(df.corr(numeric_only=True), annot=True, cmap="coolwarm")
plt.show()

Reference: the official pandas user guide and seaborn tutorial cover every plotting/summary function above in depth.

1.4 The End-to-End Process of Building an ML Model

  1. Problem definition — what exactly are you predicting, and how will you measure success?
  2. Data collection — surveys, databases, APIs, scraping, sensors.
  3. EDA, cleaning & preprocessing — covered in this module.
  4. Feature engineering & selection — turning raw columns into model-ready signal.
  5. Train/test split — hold out data the model never sees during training, to test honestly.
  6. Model training — fit an algorithm's parameters to the training data.
  7. Evaluation — measure performance on the held-out test set with the right metric.
  8. Hyperparameter tuning — covered in Module 04.
  9. Deployment & monitoring — ship the model, watch for performance drift over time.

1.5 Data Cleaning

Definition
Data cleaning is fixing or removing incorrect, corrupted, duplicate, or incomplete data so the dataset accurately represents what it's supposed to represent.

Common problems & fixes

ProblemTypical fix
Missing valuesDrop rows/columns, or impute with mean/median/mode, or a model-based imputer
Duplicate rowsdf.drop_duplicates()
Inconsistent formatting ("NY" vs "New York")Standardize categories with mapping/regex
Wrong data types (numbers stored as text)pd.to_numeric(), astype()
Outliers from data-entry errorsCap (winsorize), remove, or verify against source
Structural errors (typos in category labels)Fuzzy matching / manual mapping
Python
# missing values
df["age"] = df["age"].fillna(df["age"].median())

# drop exact duplicates
df = df.drop_duplicates()

# fix inconsistent category text
df["city"] = df["city"].str.strip().str.title()

# enforce correct dtype
df["price"] = pd.to_numeric(df["price"], errors="coerce")
Why it matters
Every downstream step — EDA conclusions, feature engineering, and the model itself — inherits any mistake left in this step. Most real-world ML failures trace back to dirty data, not a bad algorithm.

1.6 Data Preprocessing

Definition
Preprocessing is the broader step of transforming cleaned data into a numerical, consistent format a machine learning algorithm can actually consume — since most algorithms only understand numbers.

Data cleaning fixes correctness; preprocessing prepares format. It typically includes:

  • Handling categorical variables → encoding (next topic).
  • Putting numeric features on comparable ranges → scaling / normalization.
  • Splitting date/time fields into usable parts (year, month, weekday).
  • Train/test splitting so preprocessing steps (like scalers) are fit only on training data to avoid data leakage.
Common mistake: data leakage
Never fit a scaler, encoder, or imputer on the whole dataset before splitting. Fit only on the training set, then use that same fitted transformer to .transform() the test set. Otherwise information from the test set "leaks" into training and your evaluation becomes overly optimistic.

1.7 Encoding & Its Types

Definition
Encoding converts categorical (text-based) columns into numeric form, since almost all ML algorithms require numeric input.

1. Label Encoding

Assigns each category an integer: e.g. Red=0, Green=1, Blue=2. Simple, but it implies a false order/magnitude (Blue is not "greater than" Red) — safe mainly for ordinal data that genuinely has order (Low < Medium < High).

from sklearn.preprocessing import LabelEncoder
le = LabelEncoder()
df["size_encoded"] = le.fit_transform(df["size"])  # Low, Medium, High → 0,1,2 (alphabetical!)

2. One-Hot Encoding

Creates a new binary (0/1) column for every category, so no false order is implied. Best for nominal data (no inherent order) with a small-to-moderate number of categories.

pd.get_dummies(df["city"], prefix="city")
# city_Delhi  city_Mumbai  city_Pune
#     1            0            0
#     0            1            0

3. Ordinal Encoding

Like label encoding, but you explicitly define the order — used when the category order genuinely matters (e.g. education level: High School < Bachelor's < Master's < PhD).

4. Target / Mean Encoding

Replaces a category with the mean of the target variable for that category. Powerful for high-cardinality columns (e.g. thousands of zip codes) but risks leakage/overfitting if not done carefully with cross-validation folds.

When to pick which

  • Ordinal data → Label/Ordinal encoding
  • Nominal, few categories → One-Hot
  • Nominal, very many categories → Target encoding or embeddings

Pitfalls

  • One-Hot on high-cardinality columns → huge sparse matrices ("curse of dimensionality")
  • Label Encoding on nominal data → tree models are fine, but linear/distance-based models will misread it as ordered

1.8 Feature Transformation

Definition
Applying a mathematical function to a feature to change its distribution or relationship with the target — usually to make skewed data more "normal" (bell-shaped), which many algorithms assume or perform better under.
  • Log transform — log(x+1) — compresses long right tails (income, prices).
  • Square root transform — milder version of log, works for moderate skew.
  • Box-Cox / Yeo-Johnson — a family of power transforms that automatically finds the best exponent to make data closer to normal.
import numpy as np
df["income_log"] = np.log1p(df["income"])  # log(1+x), safe for x=0

1.9 Feature Scaling & Normalization

Definition
Scaling puts all numeric features on a comparable range so that features with naturally large values (like "salary" in the 10,000s) don't dominate features with small values (like "age" in the tens) purely due to their unit, not their actual importance.

Standardization (Z-score scaling)

z = (x − μ) / σ
μ = mean of the feature, σ = standard deviation. Result: mean 0, std 1.
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled  = scaler.transform(X_test)  # fit on train ONLY

Normalization (Min-Max scaling)

x' = (x − x_min) / (x_max − x_min)
Squashes every value into a fixed [0, 1] range.
from sklearn.preprocessing import MinMaxScaler
scaler = MinMaxScaler()
X_train_scaled = scaler.fit_transform(X_train)
StandardizationNormalization (Min-Max)
Not bounded to a fixed rangeBounded to [0, 1]
Less sensitive to outliersVery sensitive to outliers (they stretch the range)
Preferred for: linear/logistic regression, SVM, PCA, neural netsPreferred for: algorithms needing bounded inputs, image pixel data
Do tree-based models need scaling?
No. Decision Trees, Random Forest, XGBoost split on raw threshold values and are unaffected by feature scale. Scaling matters for distance-based (KNN, K-Means), gradient-based (linear/logistic regression, neural nets), and variance-based (PCA) algorithms.

1.10 Feature Engineering

Definition
Creating new, more informative features from existing raw data using domain knowledge — often the single highest-leverage step in the whole pipeline, more impactful than swapping algorithms.
  • Combining columns — BMI = weight / height²
  • Extracting from dates — day of week, is-weekend, month, days-since-signup
  • Binning — turning continuous age into buckets: child/adult/senior
  • Text features — word count, presence of a keyword
  • Interaction features — multiplying two features that jointly affect the target
The 80/20 of ML
Practitioners often say: "better features beat a better algorithm." A simple linear regression with well-engineered features frequently beats a complex model trained on raw, unprocessed columns.

1.11 Feature Selection

Definition
Choosing the subset of features that actually contribute useful signal to predicting the target, and dropping the rest — reduces overfitting, training time, and noise.

1. Filter Methods

Select features using statistical tests, independent of any ML model — fast and model-agnostic. Rank features and keep the top-K.

  • Correlation coefficient — drop features with near-zero correlation to the target, or drop one of two features highly correlated with each other (multicollinearity).
  • Chi-Square test — for categorical feature vs. categorical target.
  • ANOVA F-test — for numeric feature vs. categorical target.
  • Variance Threshold — drop features that barely vary (near-constant columns carry no information).
from sklearn.feature_selection import SelectKBest, f_classif
selector = SelectKBest(score_func=f_classif, k=10)
X_selected = selector.fit_transform(X_train, y_train)

2. Wrapper Methods

Use the actual ML model's performance to evaluate feature subsets — slower but accounts for feature interactions. Example: Recursive Feature Elimination (RFE) — repeatedly trains the model, drops the least important feature, and repeats.

from sklearn.feature_selection import RFE
from sklearn.linear_model import LogisticRegression
rfe = RFE(estimator=LogisticRegression(), n_features_to_select=10)
X_selected = rfe.fit_transform(X_train, y_train)

3. Embedded Methods

Feature selection happens as part of model training itself — the algorithm naturally assigns low/zero importance to useless features.

  • Lasso Regression (L1 regularization) — shrinks unimportant feature coefficients exactly to zero.
  • Tree-based feature importance — Random Forest / XGBoost expose a feature_importances_ score for free after training.
from sklearn.linear_model import Lasso
lasso = Lasso(alpha=0.01)
lasso.fit(X_train, y_train)
# coefficients that became exactly 0 → those features were "deselected"
