Deep Learning III — RNN, LSTM & GRU

CNNs are built for grid-shaped data with no sense of order. This module covers the architectures built specifically for data where order is the whole point — text, speech, time series.

8.1 Sequential vs. Non-Sequential Data

Definition
Non-sequential data — each sample is independent; shuffling the rows of a dataset doesn't change its meaning (a table of house prices, an image dataset). Sequential data — order carries meaning; shuffling it destroys the information ("dog bites man" vs "man bites dog" — same words, different order, opposite meaning).
Non-sequentialSequential
Tabular data (Module 01–04 examples)Sentences, speech audio, stock prices, DNA sequences, video frames
CNNs, tree models, standard ANNRNN, LSTM, GRU, Transformers
Why ANN/CNN alone don't fit sequences
A plain ANN takes a fixed-size input and has no built-in memory of what came before — it treats "I love this movie" and "this movie I love" identically if you just flatten the words into input slots. We need a model with a memory of previous inputs, and one that handles variable-length sequences.

8.2 Sequential Models & RNN Architecture

Definition
A Recurrent Neural Network (RNN) processes a sequence one element at a time, and at every step carries forward a hidden state — a running summary of everything seen so far — which is combined with the new input to produce the next hidden state.
hₜ = tanh(Wₓₕ·xₜ + Wₕₕ·hₜ₋₁ + b)
xₜ = input at time step t, hₜ₋₁ = previous hidden state (the "memory"), hₜ = new hidden state
The same weights (Wₓₕ, Wₕₕ) are reused at every time step — this weight sharing is what lets an RNN handle sequences of any length.

Types of RNN by input/output shape

TypeExample
One-to-manyImage captioning — one image in, a sequence of words out
Many-to-oneSentiment analysis — a sentence in, one label out
Many-to-manyMachine translation, video frame labeling

8.3 RNN vs. ANN — The Key Difference

ANN (Module 06)RNN
Fixed-size input, no memory between samplesVariable-length input, carries a hidden state across time steps
Every input treated independentlyCurrent output depends on current input and everything seen before
Different weights per layerSame weights reused at every time step (parameter sharing across time)
Backprop: standard backpropagationBackprop: Backpropagation Through Time (BPTT) — gradients flow backward through every time step

8.4 The Problem with Vanilla RNNs

Vanishing & Exploding Gradients — again, but worse
BPTT multiplies gradients across every time step, just like backprop multiplies across every layer (Module 06) — except a long sequence can have hundreds or thousands of "layers" (time steps). Repeated multiplication by the same recurrent weight matrix Wₕₕ makes gradients either shrink toward zero (vanishing — the network "forgets" long-range context) or grow explosively (exploding — training becomes unstable). This is the core limitation that made vanilla RNNs impractical for long sequences.

Concretely: a vanilla RNN trying to answer "The clouds are in the ___" (predict "sky") does fine — the relevant context is close by. But "I grew up in France... [200 words later] ...I speak fluent ___" needs the model to remember "France" across 200 steps — vanilla RNNs largely fail at this.

8.5 LSTM (Long Short-Term Memory)

Definition
LSTM fixes the vanishing gradient problem by adding a separate cell state — a conveyor belt that carries long-term memory largely unchanged across time steps — and three gates that learn what to add to it, remove from it, and read from it.

The Three Gates

Forget gate: fₜ = σ(W_f·[hₜ₋₁, xₜ] + b_f)
Decides what fraction of the old cell state to keep vs. throw away. Output near 0 = forget, near 1 = keep.
Input gate: iₜ = σ(W_i·[hₜ₋₁, xₜ] + b_i), candidate: C̃ₜ = tanh(W_C·[hₜ₋₁, xₜ] + b_C)
Decides what new information to write into the cell state: Cₜ = fₜ*Cₜ₋₁ + iₜ*C̃ₜ
Output gate: oₜ = σ(W_o·[hₜ₋₁, xₜ] + b_o), hₜ = oₜ * tanh(Cₜ)
Decides what part of the (updated) cell state to expose as this step's hidden state / output.

All three gates use sigmoid (output 0–1, acting as a "how much to let through" valve) — this is exactly why sigmoid earns a place in Module 06's activation function list beyond just output layers.

tf.keras.layers.LSTM(64, return_sequences=False)

Advantages

  • Handles long-range dependencies far better than vanilla RNN
  • Gates let the network learn what to remember/forget

Disadvantages

  • More parameters and slower to train than a vanilla RNN
  • Still processes sequentially — can't parallelize across time steps (unlike Transformers, next module)

8.6 GRU (Gated Recurrent Unit)

Definition
GRU is a simplified LSTM: it merges the cell state and hidden state into one, and reduces three gates to two — update gate and reset gate — giving comparable performance to LSTM on many tasks with fewer parameters and faster training.
  • Update gate — decides how much of the past hidden state to keep vs. replace with the new candidate (merges LSTM's forget + input gates into one).
  • Reset gate — decides how much of the past hidden state to "forget" when computing the new candidate state.
tf.keras.layers.GRU(64)
LSTMGRU
